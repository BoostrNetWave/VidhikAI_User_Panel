# ANTIGRAVITY — Vidhik AI Complete Frontend Redesign Prompt

## ROLE

You are acting as a **principal frontend engineer + senior product designer + design-system engineer**.

Your task is to completely redesign the existing Vidhik AI user-facing frontend into a polished, premium, production-grade SaaS interface.

The result must look like it was designed and implemented by an experienced frontend/product team — **not generated by AI and not assembled from a generic dashboard template**.

---

# SOURCE OF TRUTH

Use these files as the primary product context:

1. `design.md`
2. `architecture.md`
3. Existing frontend source code
4. Existing routes
5. Existing components
6. Existing API/service layer
7. Existing user workflow
8. Existing brand identity/assets

The redesigned `design.md` is the visual source of truth.

The redesigned `architecture.md` is the frontend architecture source of truth.

If existing source code conflicts with the new visual specification, change the UI implementation while preserving functional behavior and API contracts.

---

# PRIMARY OBJECTIVE

Perform a **complete visual and interaction redesign** of the user section.

Do not perform a superficial restyling.

Do not simply:

- change colors
- increase border radius
- add shadows
- add gradients
- replace buttons
- wrap existing components in cards

Instead, rethink the information hierarchy, spacing, composition, navigation, states, interaction patterns and component architecture.

The result should feel like a mature SaaS product.

# 3. Do NOT create an AI-looking interface

Absolutely avoid:

- purple-blue AI gradients
- glowing cards
- excessive glassmorphism
- neon borders
- floating blobs
- giant rounded rectangles
- gradient text
- excessive animations
- decorative AI illustrations
- random sparkles
- excessive badges
- emoji as UI icons
- giant dashboard cards
- generic "AI-powered" marketing copy throughout the app

Use restrained premium SaaS design.

---

# 4. Design Quality Standard

Every screen must pass this mental test:

> "Could this have shipped from a serious SaaS company after multiple rounds of product design review?"

If the answer is no, refine it.

Pay special attention to:

- alignment
- spacing
- visual hierarchy
- information density
- typography
- interaction states
- empty states
- loading states
- error states
- responsive behavior
- accessibility

# 19. Refactor Strategy

Create a proper design system first.

Implement:

```text
Design tokens
↓
Global CSS
↓
shadcn/ui primitives
↓
AppShell
↓
Page primitives
↓
Feature components
↓
Pages
```

Create reusable primitives instead of duplicating markup.

# 21. Micro-interactions

Use subtle motion only when useful.

Examples:

- hover: 120–180ms
- dialog: 180–240ms
- page transitions: 200–300ms
- skeleton pulse
- button loading state

Respect `prefers-reduced-motion`.

# 22. Pixel-Precision Requirement

After implementation, inspect every screen for:

- 4px/8px spacing inconsistencies
- misaligned icons
- inconsistent button heights
- incorrect input padding
- inconsistent border radius
- inconsistent text weights
- incorrect line heights
- card padding differences
- broken responsive behavior
- overflow
- table density
- modal spacing
- sidebar alignment

Perform at least one dedicated visual-polish pass after functionality is working.

---

# 23. Do Not Stop at the First Acceptable Result

The first implementation is a baseline.

After implementation:

1. inspect the rendered UI
2. identify generic-looking areas
3. improve hierarchy
4. normalize spacing
5. remove unnecessary decoration
6. improve empty/loading/error states
7. improve responsive behavior
8. improve typography
9. improve interaction states
10. perform final consistency pass
